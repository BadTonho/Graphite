# Superfície da API de extensões

Extensões VSIX rodam no extension host oficial do Code OSS 1.145.2, em um processo Node separado iniciado por `packaging/code-oss/bridge.mjs`. O Graphite responde às chamadas que o host faz à thread principal, então todo efeito no workbench passa pelas verificações do próprio Graphite (confiança do workspace, arquivos somente leitura e a fronteira do workspace).

## Suportado

| Área | O que funciona |
|---|---|
| Comandos | Registrar, executar e listar comandos; comandos do Graphite podem ser executados pelas extensões. |
| Configuração | Ler valores, atualizar e remover configurações do workspace ou do usuário, escutar mudanças. |
| Storage | Storage global e do workspace da extensão. |
| Prompts | `showInputBox`, `showQuickPick` e `showInformationMessage` com botões de ação. |
| Edições | `TextEditor.edit`, `workspace.applyEdit` e documentos abertos ou exibidos no editor. |
| Provedores de linguagem | Hover, completion, formatação de documento, diagnósticos, definição, declaração, definição de tipo, implementação, referências, símbolos de documento, code actions, renomear e ajuda de assinatura. Também formatação de intervalo (**Formatar seleção**; a linha do cursor quando nada está selecionado), inlay hints, destaques de documento e regiões de folding; os três últimos são pedidos automaticamente (veja abaixo). Selection ranges comandam **Expandir seleção** no lugar da expansão pela árvore sintática quando uma extensão os fornece. A formatação ao digitar roda durante a digitação quando `editor.formatOnType` está ligado. Hierarquias de chamadas e de tipos (**Show Call Hierarchy** / **Show Type Hierarchy**) listam chamadores e chamados, ou supertipos e subtipos, no seletor de locais. Links de documento são sublinhados e seguidos com Ctrl+clique. Tokens semânticos são desenhados sobre as cores da sintaxe. Code lenses aparecem no fim da linha e rodam com Ctrl+clique ali. Cores são pintadas e contornadas no texto. |
| Links | `window.openUri` abre links `https://` no navegador padrão; outros esquemas são recusados. `env.asExternalUri` devolve o link sem alterações. |
| Output | `window.createOutputChannel` grava em um arquivo de log. Mostrar o canal abre o log em uma view somente leitura, que se atualiza enquanto a extensão escreve. |
| Barra de status | Itens de `window.createStatusBarItem` aparecem no fim da barra de status com o texto. Clicar em um item executa o comando dele: um comando da extensão, se registrado, ou um comando do Graphite. |
| Arquivos | `workspace.findFiles` com globs de inclusão e exclusão e limite de resultados, respeitando arquivos de ignore. `workspace.findTextInFiles` (API proposta: a extensão deve listar `findTextInFiles` em `enabledApiProposals`) busca no workspace com o mecanismo de busca de projeto, com opções de regex, maiúsculas, palavra inteira e globs, e para após 5 segundos. |
| Progresso | Títulos e mensagens de `withProgress` aparecem na barra de status. |
| Terminal | `window.createTerminal` (com `name`, `shellPath`, `shellArgs`, `cwd`) abre uma aba de terminal do Graphite. `sendText`, `show`, `hide`, `dispose` e `onDidCloseTerminal` com o código de saída funcionam. |
| Observadores de arquivos | `workspace.createFileSystemWatcher` recebe eventos de criação, alteração e exclusão do workspace inteiro (exceto dentro de `node_modules`) e das pastas que a extensão registra fora dele. |
| Área de transferência | `env.clipboard.readText` e `writeText`. |
| `workspace.fs` | Respondido pelo próprio extension host direto no disco local; não passa pelo Graphite. |
| Decorações de texto | `window.createTextEditorDecorationType` e `TextEditor.setDecorations` desenham cores de fundo, bordas (`border`, `outline`), marcas de linha inteira e texto `after` no fim da linha, com variantes `dark` e `light`. As cores podem ser hex, `rgb()`/`rgba()` ou cores de tema comuns. Fontes, ícones de gutter, marcas da régua, texto `before` e mensagens de hover são ignorados, e as decorações ainda não são desenhadas no modo de quebra de linha. Os intervalos não são ajustados durante a edição; a extensão normalmente os define de novo. |
| Adaptadores de depuração | Uma extensão que registra um `DebugAdapterDescriptorFactory` pode fornecer o adaptador do seu tipo de depuração: descritores de executável e de servidor TCP local funcionam. Provedores de configuração, named pipes e implementações inline ainda não são suportados. Veja [Painel de depuração](debug-panel.md). |
| Webview | Vários painéis webview, conteúdo HTML, mensagens nos dois sentidos; URIs de recursos ficam restritas a `localResourceRoots` (ou às raízes da extensão e do workspace). |
| Serializadores de notebook | Um tipo de `contributes.notebooks` atendido por `workspace.registerNotebookSerializer` abre seus arquivos no editor de notebook do Graphite: o arquivo é lido com `deserializeNotebook`, mostrado como células e gravado com `serializeNotebook` ao salvar. O editor trabalha sobre um espelho em `<perfil>/notebook-mirror`, então a aba se chama `<arquivo>.ipynb`; salvar o espelho grava o arquivo real pelo serializador e nunca grava o texto `.ipynb` nele. A linguagem da célula fica nos metadados da célula. Arquivos `.ipynb` mantêm o editor Jupyter embutido. Os itens de saída são convertidos entre a forma da extensão e as saídas do notebook (streams, erros, texto, JSON e imagens). |
| Controladores de notebook | Um controlador de `notebooks.createNotebookController` aparece no seletor de kernels dos notebooks do seu tipo, ao lado dos kernels Jupyter. Executar uma célula envia à extensão o notebook (com um documento de texto por célula) e `$executeCells`; a execução que ela cria (`createNotebookCellExecution`) devolve as saídas (`replaceOutput`, `appendOutput`, `replaceOutputItems`, `appendOutputItems`), o `executionOrder` e o estado final, e interromper uma execução chama o `interruptHandler` do controlador. As células rodam em ordem e usam os mesmos estados de execução, fila e saídas de um kernel Jupyter. O notebook é enviado à extensão quando uma célula é executada, não a cada edição. Renderizadores, mensagens do controlador, provedores de variáveis, ações de origem de kernel e execuções no nível do notebook não são suportados. |
| Editores customizados | Uma entrada `contributes.customEditors` abre seus arquivos na webview da extensão em vez do editor de texto, para provedores registrados com `registerCustomTextEditorProvider` e `registerCustomEditorProvider`. A extensão é ativada por `onCustomEditor:<viewType>`, os arquivos que casam com um seletor `priority: "default"` abrem com ela, e **Reabrir editor com...** (`workbench.action.reopenWithEditor`) lista os outros editores e o editor de texto; essa escolha é lembrada para o arquivo. A página fica em uma sobreposição abaixo da faixa de abas, com `enableScripts`, confinamento de raízes de recursos e mensagens nos dois sentidos como nas outras webviews. Um editor de **texto** trabalha sobre o documento de texto aberto, então salvar, desfazer e refazer são os do próprio documento. Um editor **customizado** é dono do documento: o texto atrás dele fica somente leitura, as edições informadas por `onDidChangeCustomDocument` deixam a aba suja, e Salvar, Desfazer e Refazer (menu, paleta e teclas) são enviados à extensão como `saveCustomDocument`, `undo` e `redo`. Um arquivo aberto por uma extensão (`openTextDocument`) nunca abre em um editor customizado. Backups, salvar como, reverter, mover um editor entre grupos, editores de diff e o widget de busca não são suportados. |
| Autenticação | `authentication.getSession` e `getAccounts` funcionam para o provedor `github`, atendido pelo próprio login do GitHub do Graphite (veja [Login no GitHub](github-sign-in.md)), e para provedores que uma extensão registra com `registerAuthenticationProvider` (`getSessions`, `createSession`, `removeSession` e `onDidChangeSessions` são repassados). Uma extensão só recebe uma sessão depois que o usuário escolheu **Permitir** para aquela conta em um aviso; a escolha é guardada por provedor, conta e extensão em `<perfil>/code-oss/authentication-access.json`, e uma extensão que cria a sessão com `createIfNone` fica permitida para ela. Pedidos `silent` nunca perguntam e devolvem `undefined` até a extensão ser permitida. Um pedido com escopos que o login do GitHub não tem oferece um novo login com os escopos combinados. Sair do GitHub ou chamar `removeSession` esquece as extensões permitidas daquela conta. Pedidos por desafio `WWW-Authenticate` e provedores dinâmicos (servidor OAuth) não são suportados. |
| Sistemas de arquivos virtuais | `workspace.registerFileSystemProvider` atende um esquema de URI. Abrir um documento `scheme:` (`openTextDocument`, `showTextDocument` ou um clique no explorer) lê o arquivo pelo provedor para um espelho local em `<perfil>/virtual-fs/<scheme>/<autoridade>/<caminho>` e abre esse arquivo, então realce e servidores de linguagem funcionam como em qualquer arquivo. As extensões veem o documento com a URI virtual, e salvar grava o espelho de volta com `writeFile`. Um documento limpo é atualizado a partir do provedor a cada abertura; um com edições não salvas as mantém. Cada esquema registrado aparece no explorer abaixo da árvore do workspace como uma pasta `scheme:/`, cujas subpastas são lidas com `readDirectory` ao expandir e relidas em `onDidChangeFile`. O Graphite observa a raiz com `watch`. Provedores que declaram a capacidade `Readonly` são registrados como tal. As chamadas de exclusão, renomeação e stat existem para o explorer, mas nenhum menu as usa ainda, e a parte de query da URI não faz parte da identidade de um arquivo. |
| Controle de versão | Provedores de `scm.createSourceControl` aparecem no painel de Controle de Código abaixo das alterações do Git: um cabeçalho com o rótulo e a contagem, uma caixa de commit, grupos de recursos recolhíveis (respeitando `hideWhenEmpty`) e os recursos com tooltip e decorações de tachado e esmaecido. Digitar na caixa atualiza `inputBox.value`, e `Ctrl+Enter` (ou o botão de confirmação) executa `acceptInputCommand`. Clicar em um recurso executa o comando associado a ele; um recurso `file:` sem comando abre como arquivo. Sem repositório Git, o painel lista apenas os provedores de extensão. Quick diff, o provedor de histórico e o botão de ação não são exibidos. |
| Webview views | Uma entrada de `contributes.views` com `"type": "webview"` é atendida por `window.registerWebviewViewProvider`. O Graphite chama `resolveWebviewView` na primeira vez que a view é mostrada, hospeda a página dela em uma sobreposição sobre a barra lateral, abaixo de uma linha de cabeçalho, e informa as mudanças de visibilidade (`onDidChangeVisibility`). Scripts só rodam com `enableScripts`, e uma Content Security Policy restritiva sempre se aplica. As mensagens (`postMessage`) funcionam nos dois sentidos, e `title`, `description` e `badge` atualizam o cabeçalho. Uma view oculta descarta a página e a recria a partir do último HTML, a menos que o provedor use `retainContextWhenHidden`. Várias webview views no mesmo contêiner dividem a altura; ao lado de views de árvore, ocupam a metade inferior. `WebviewView.show()` revela o contêiner. |

## Contribuições declarativas

Um VSIX sem ponto de entrada Node.js (temas, snippets, pacotes de idioma) não executa código, então pode ser habilitado sem iniciar o extension host. Contribuições aplicadas:

| Contribuição | O que acontece |
|---|---|
| `commands` | Os comandos declarados aparecem na paleta antes da extensão ativar. |
| Configuração de `languages` | Os marcadores de comentário de linha e de bloco alimentam Alternar Comentário de Linha/Bloco. |
| `viewsContainers.activitybar` | Os contêineres aparecem na barra de atividades. |
| `snippets` | Os arquivos de snippets são carregados para extensões habilitadas, com escopo na linguagem contribuinte. Um snippet do usuário ou do projeto com o mesmo prefixo e escopo os substitui. |

| `themes` | Os temas de cores são importados para o perfil e selecionados com `workbench.colorTheme`, por rótulo ou id. Desabilitar a extensão os remove. |
| `iconThemes` | Os temas de ícones de arquivo são selecionados com **Tema de Ícones de Arquivo** ou `workbench.iconTheme`, e desenhados no Explorer, no Quick Open, nas abas e no Controle de Versão. Veja [Ícones de arquivos](file-icons.md#temas-de-ícones-de-extensões). |

Atalhos de teclado são vinculados ao keymap ativo quando a extensão é aprovada e o workspace é confiável. Gramáticas constam no pacote, mas ainda não são aplicadas.

## Ainda não

- Provedores de linguagem além da lista acima (nenhum que o Graphite conheça; o seletor de cor e as apresentações de cor não são suportados). Code actions que apenas executam um comando da extensão, e operações de arquivo dentro de uma renomeação, não são aplicadas.

Chamadas fora desta lista recebem o erro `Graphite does not support <actor>.<method>`, e a extensão recebe esse erro. Registros de capacidades não implementadas (`$register*`, `$unregister*`, `$emit*`) são aceitos sem erro para não poluir a barra de status. Cada chamada não suportada é registrada uma vez por sessão em `<perfil>/code-oss/unsupported-api.log`, que mostra o que uma extensão precisa e o Graphite ainda não oferece.

Os comandos são registrados do mesmo modo. Quando uma extensão chama `commands.executeCommand` com um id que o Graphite não tem, ou executa uma code lens cujo comando o Graphite não consegue rodar, o id é contado, e **Mostrar comandos pedidos pelas extensões** abre uma lista somente leitura (pedidos, id do comando, se veio do código da extensão ou de uma code lens), do mais pedido para o menos. Cada id também é anexado uma vez a `<profile>/code-oss/requested-commands.log`. Use a lista para ver quais comandos implementar para a extensão funcionar; a lista é refeita a cada sessão, o log guarda os ids entre reinícios.

## Recursos pedidos automaticamente

A maioria dos provedores responde a um comando (hover, ir para definição, formatar). Sete são pedidos sem comando:

- **Inlay hints** (`registerInlayHintsProvider`): para o documento ativo, sempre que o texto muda. São mostrados pelo mesmo recurso de dicas embutidas que os servidores de linguagem usam, e só quando nenhum servidor de linguagem atende o arquivo, para os dois nunca competirem. Um provedor que falha não é consultado de novo até o documento mudar.
- **Destaques de documento** (`registerDocumentHighlightProvider`): para o símbolo sob o cursor, depois que o cursor ficou parado por 150 ms. As ocorrências são desenhadas com a cor de destaque de palavra do editor. Os destaques somem assim que o cursor se move, e uma resposta para uma posição que o cursor já deixou é descartada.
- **Regiões de folding** (`registerFoldingRangeProvider`): para o documento ativo, sempre que o texto muda. Enquanto as regiões de um provedor descrevem o texto atual, elas substituem as regras de indentação em todos os comandos de dobra e na exibição; até a primeira resposta, ou após uma edição, vale o folding por indentação. Regiões que não cobrem duas linhas são descartadas, e um provedor que falha não é consultado de novo até o documento mudar.
- **Links de documento** (`registerDocumentLinkProvider`): para o documento ativo, sempre que o texto muda. Os links são sublinhados; Ctrl+clique em um abre links `https:` no navegador e links `file:` no editor. Links que o provedor deixa sem resolver (ainda sem URL) são informados mas não seguidos, e os sublinhados somem assim que o texto é editado, até a extensão responder de novo.
- **Tokens semânticos** (`registerDocumentSemanticTokensProvider`): para o documento ativo, sempre que o texto muda. A resposta completa do provedor (tipo, posição e tamanho de cada token) é decodificada, cada tipo de token é mapeado para a classe de sintaxe mais próxima (tipos, funções, variáveis, propriedades, palavras-chave, comentários, strings, números, operadores; outros tipos mantêm a cor da sintaxe) e desenhada sobre o realce do tree-sitter. Os tokens descrevem uma revisão do texto, então após uma edição valem as cores da sintaxe até o provedor responder de novo. Só respostas do documento inteiro são entendidas: respostas delta, provedores de intervalo e modificadores de token não são usados. O extension host envia a resposta binária ao Graphite como palavras de 32 bits, e a decodificação segue o layout do Code OSS conforme a descrição do protocolo; foi testada com respostas sintéticas, não com uma extensão de linguagem real.
- **Code lenses** (`registerCodeLensProvider`): para o documento ativo, sempre que o texto muda. O Graphite não tem espaço entre as linhas do editor, então cada lens aparece como texto discreto no fim da própria linha, e várias na mesma linha são unidas por ` | ` na ordem das colunas. Lenses que chegam sem comando são resolvidas uma a uma (até 50 por revisão do documento) e o texto vai se completando conforme as respostas chegam. Ctrl+clique bem no fim de uma linha, ou **Executar code lens da linha atual**, executa a primeira lens da linha: um comando do Graphite roda com o primeiro argumento da lens, um comando de extensão roda no extension host com todos os argumentos, e qualquer outro (por exemplo o `editor.action.showReferences` embutido do VS Code) é informado como indisponível. O texto some quando o documento é editado, até o provedor responder de novo.
- **Cores** (`registerColorProvider`): para o documento ativo, sempre que o texto muda. Sem widgets embutidos não há um quadradinho antes do texto: cada trecho de cor é desenhado com um fundo translúcido nessa cor e um contorno da mesma cor. As cores somem assim que o texto é editado, até o provedor responder de novo. Escolher outra cor a partir de um quadrado (`provideColorPresentations`) não é suportado.

Os dois só são pedidos em workspace confiável, para o documento ativo, e respostas para uma revisão desatualizada do documento são descartadas. Cada pedido tem limite de 10 segundos. Esses caminhos são cobertos por testes unitários que fazem o papel do extension host no protocolo; não foram executados com extensões de terceiros.

### Formatação ao digitar

Com `"editor.formatOnType": true` (desligado por padrão, como no VS Code), digitar um dos caracteres de gatilho que uma extensão registrou com `registerOnTypeFormattingEditProvider` pede a ela que formate em volta do cursor; as edições são aplicadas como um passo desfazível. Só contam caracteres digitados um a um (não texto colado), só com um cursor e só se o documento não mudou nesse meio tempo. Digitar Enter ainda não dispara.
