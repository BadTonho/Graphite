# v0.6 — Depuração, Webviews e ferramentas de desenvolvimento

Esta implementação adiciona um cliente DAP local por stdio com perfis launch e attach de `.vscode/launch.json`, controles de execução, breakpoints de linha (incluindo campos condicionais, de contagem e mensagem de log), um painel de depuração de três colunas com pilha de chamadas, árvore de variáveis, watches, exception breakpoints e console interativo (veja [Painel de depuração](debug-panel.md)). Iniciar um adaptador exige confiança no workspace. A paleta inclui ações de depuração e os atalhos padrão F5/F10/F11.

No Windows, o Wry hospeda WebView2 como janela filha. Webviews de extensões usam uma política CSP restritiva, ponte IPC com limite de tamanho e o caminho de mensagens de Webview do VS Code. No Linux, o host GTK/WebKitGTK atual é uma janela GTK separada e ainda precisa de integração e validação nativa em X11 e Wayland.

As prévias de Markdown e PNG usam o WebView nativo. A rolagem do Markdown sincroniza editor e prévia pela proporção do documento; as prévias de imagem mostram dimensões e tamanho do arquivo e aceitam comandos de zoom. O Test Explorer consome descoberta do VSIX TestController, perfis de execução, estado, saída e cancelamento pelos atores oficiais do host de extensões. Os provedores vêm das extensões. Portas locais filtra a inspeção de listeners aos processos iniciados pelo Graphite e só permite encerrar processos registrados; exposição de rede e encaminhamento remoto ficam fora do escopo.

A confiança no workspace protege a inicialização de adaptadores, execução de testes e criação de Webviews de extensões. A revogação cancela testes, encerra o adaptador de depuração e fecha o Webview.

## Limites atuais de validação

No Windows (2026-11-13), `cargo build --workspace --offline` passa e `cargo test --workspace --offline` reporta 689 aprovados, 0 falhos e 9 ignorados (os ignorados precisam do runtime Code OSS empacotado ou de rede). Verificações da interface nativa não foram feitas, e os caminhos do extension host (adaptadores de depuração e provedores de linguagem de extensões) são cobertos por testes que fazem o papel do host no protocolo, não por extensões reais de terceiros; veja o checklist manual do Windows. Linux, WebKitGTK, X11 e Wayland não foram compilados nem exercitados neste ambiente Windows. A janela GTK de topo no Linux é uma limitação de integração conhecida. Decoradores de execução no gutter do Test Explorer ainda não foram implementados.
