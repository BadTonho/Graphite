# v0.4 — Git, layout avançado e ferramentas

## Git e controle de código-fonte

Abra o Source Control com `Ctrl+Shift+G`. O painel lista caminhos staged, unstaged, não rastreados e em conflito. Selecione uma linha e pressione `S` para adicionar ao stage, `U` para remover do stage, `H` para adicionar o primeiro hunk, `R` para abrir um conflito ou `C` para informar a mensagem do commit. No editor, `Ctrl+K Ctrl+H` adiciona ao stage a linha do cursor, `Ctrl+K Ctrl+Shift+H` reverte essa linha e `Ctrl+K Ctrl+R` reverte o primeiro hunk. As alterações aparecem como marcadores no gutter.

O nome da branch na barra de status abre o seletor de branches locais. O checkout é recusado quando o índice, worktree ou algum buffer aberto tem alterações; após um checkout bem-sucedido, os documentos abertos são recarregados do disco. O próprio Git também pode informar uma corrida ou outro erro de checkout. Conflitos exibem painéis base/ours/theirs. Escolha `B`, `O` ou `T` para resolver com um dos lados, ou `E` para editar o arquivo no worktree; ao salvar, a resolução é adicionada ao stage.

O status do Git é atualizado depois de operações do editor e notificações do sistema de arquivos. Leituras do repositório, alterações do índice e commits rodam em threads de trabalho. O serviço SCM atual opera em worktrees locais e requer o executável `git` para checkout de branch; status, staging no índice e commits usam `gix`.

## Visualização de diff

Execute `code -d <esquerdo> <direito>` para abrir uma comparação de dois arquivos. Pressione `Tab` na visualização para alternar entre apresentação lado a lado e em linha; `Esc` fecha. `Ctrl+Shift+D` compara o buffer ativo com a versão em HEAD, incluindo alterações ainda não salvas no buffer. O diff começa no topo dos arquivos e ainda não oferece rolagem sincronizada nem hunks de merge editáveis.

## Layout e barra de status

- `Ctrl+K Z` alterna o Zen Mode e a tela cheia.
- `Ctrl+K Ctrl+E` alterna o editor centralizado com largura máxima de 80 colunas.
- `Ctrl+K Ctrl+O` alterna o Outline na lateral direita. Selecione uma declaração para mover o cursor até ela.
- A barra de status mostra a branch Git atual, codificação, final de linha, indentações e o estado do Screencast. Clique na codificação para alternar entre UTF-8, UTF-8 com BOM, UTF-16 LE e UTF-16 BE; clique no final de linha para alternar LF/CRLF; clique na indentação para converter entre espaços e tabs. Essas alterações de formato são aplicadas no próximo salvamento.

## CLI e IPC local

O executável `code` é instalado ao lado de `graphite` e aceita:

```text
code .
code caminho/arquivo.rs
code -d esquerdo.rs direito.rs
code -g caminho/arquivo.rs:12:5
code --wait caminho/arquivo.rs
```

As solicitações são encaminhadas ao editor aberto por um socket local por usuário; se não houver editor aberto, o lançador inicia um. `--wait` retorna depois que as abas dos arquivos solicitados ou a visualização diff forem fechadas. Letras de unidade do Windows são tratadas sem confundir os dois-pontos do caminho com os separadores de linha e coluna.

## Process Explorer e Screencast Mode

Alterne o Process Explorer com `Ctrl+K Ctrl+P`. Enquanto aberto, ele mostra CPU e memória do app e dos processos descendentes, incluindo shells e servidores de linguagem. Role sobre o painel para consultar mais processos. O painel também exibe os tempos medidos de inicialização do app, criação da janela e inicialização do renderizador.

Alterne o Screencast Mode pela barra de status ou com `Ctrl+K Ctrl+S`. Um anel animado acompanha o ponteiro, e o último atalho pressionado aparece por 1,5 segundo.
