# v0.6 — Debugging, webviews and developer tools

This implementation adds a local stdio DAP client with `.vscode/launch.json` launch and attach profiles, execution controls, line breakpoints (including conditional, hit-count and log-message fields), a three-column debug panel with call stack, variable tree, watches, exception breakpoints and an interactive console (see [Debug panel](debug-panel.md)). Starting an adapter requires workspace trust. The native command palette includes the debugging actions and default F5/F10/F11 shortcuts.

Wry hosts WebView2 as a child on Windows. Extension webviews use a restrictive Content Security Policy, a size-limited IPC bridge and the VS Code webview message path. On Linux the current GTK/WebKitGTK host is a separate GTK window and needs native integration and lifecycle validation on both X11 and Wayland.

Markdown and PNG previews use the native WebView. Markdown source and preview scroll positions synchronize by document ratio; image previews show dimensions and file size and support zoom commands. Test Explorer consumes VSIX TestController discovery, run profiles, state, output and cancellation through the official extension-host test actors. Providers come from extensions. Local Ports filters listener inspection to processes Graphite started and only offers to stop those registered processes; network exposure and remote forwarding are out of scope.

Workspace trust gates adapter launch, test execution and extension webview creation. Revocation cancels test runs, stops the debug adapter and closes the webview.

## Current validation limits

On Windows (2026-11-13), `cargo build --workspace --offline` passes and `cargo test --workspace --offline` reports 689 passed, 0 failed and 9 ignored (the ignored ones need the packaged Code OSS runtime or network access). Native UI checks have not been performed, and the extension-host paths (debug adapters and language providers from extensions) are covered by tests that play the host side of the protocol, not by real third-party extensions; see the Windows manual checklist. Linux, WebKitGTK, X11 and Wayland have not been built or exercised in this Windows environment. The Linux top-level GTK window is a known integration limitation. Test Explorer gutter play decorations are not yet implemented.
