# v0.2 — Editing and customization

## Available interactions

- Select text with the mouse or `Shift` + navigation; `Ctrl+A` selects the buffer. `Ctrl+C/X/V` use the system clipboard; `Ctrl+Z/Y` undo and redo.
- Add cursors with `Alt+Click`, select the next occurrence with `Ctrl+D`, or select all occurrences with `Ctrl+Shift+L`. Typing, navigation, deletion and clipboard paste act on all cursors as a single undoable edit.
- Enter preserves the local LF or CRLF convention at each cursor. Accepting a completion replaces each selection or word prefix as one undoable edit.
- Open files in tabs, switch with `Ctrl+Tab`, and close with `Ctrl+W`. A modified tab asks whether to save, discard or cancel.
- `Ctrl+\` splits the active editor vertically; `Ctrl+K Ctrl+\` splits it horizontally. Click a group or use `F6` to move focus. Groups have independent tabs, cursors and scroll positions and share edits and history for the same document. Interactive verification of these controls is still pending.
- `Ctrl+F` opens document search and `Ctrl+H` opens search and replace. Enter selects the next match; in replace mode, Tab switches fields, Alt+Enter replaces the selected match, and Ctrl+Enter replaces all as one undoable edit. `Alt+R/C/W/P/S` toggles regex, case sensitivity, whole word, preserve case and selection scope.
- `Ctrl+Shift+F` searches workspace files in the background using ripgrep's search libraries, honoring ignore files and unsaved content; Up/Down and Enter navigate results. The project search currently uses literal text. `Ctrl+P` opens the fuzzy file picker.
- `Alt+Up/Down` moves selected line blocks; `Shift+Alt+Up/Down` duplicates them and `Ctrl+Shift+K` deletes them. `Ctrl+Shift+Alt+S/D` sorts or deduplicates selected line blocks. These operations support multiple cursors and one-step undo. `Shift+Alt+Right/Left` expands or shrinks syntax selection.
- Files with read-only filesystem permissions or a matching `files.readonlyInclude` pattern open read-only; editing and history changes are blocked, and the editor exposes the state to accessibility clients. The setting accepts glob patterns as an array or a map of patterns to booleans.
- `Ctrl+Alt+T` switches and persists the built-in light/dark palette. `Ctrl+Shift+I` imports supported VS Code settings, snippets and JSON themes into the VsCodeShoppe config directory.
- `Ctrl+Shift+P` filters imported snippet prefixes; Enter inserts the selected match.
- IME preedit is displayed and committed text is sent to the active editor or input field. The AccessKit tree exposes editor groups, their tabs, primary selections, focus, and read-only state. Screen-reader verification remains pending.
- Indentation is detected when opening files by default. `Ctrl+Shift+Alt+I` converts indentation; `files.trimTrailingWhitespace` enables trimming on save. `editor.rulers` draws configured column markers.
- Trim-on-save writes the trimmed content before applying the undoable edit to the buffer. A failed write leaves the document and its history unchanged.
- Set `editor.wordWrap` to `"on"` to wrap visually at the editor width, and set `editor.wrappingIndent` to `"none"`, `"same"`, `"indent"` or `"deepIndent"` for continuation lines. `"off"` disables wrapping. Visual wrapping does not change the document. Interactive verification remains pending.

## Supported imported settings

`editor.fontSize`, `editor.tabSize`, `editor.insertSpaces`, `workbench.colorTheme`, and the supported editor/sidebar/status color keys are applied. JSON/JSONC themes can inherit other files in the imported theme directory; extension theme labels are read from their manifests. Cycles, invalid references and unsupported `tokenColors` formats are reported. Theme token colors for keywords, functions, types, strings, numbers, comments and variables are mapped to editor syntax classes. Other settings are reported as ignored. Imported files are copied; originals are not modified. Project search skips unreadable files. Snippet tab stops are reduced to their default text; choices and variable substitution are not expanded.

Editor font size, tab size, insert-spaces, indentation detection, trim-on-save, rulers, read-only patterns and theme settings are loaded in order from imported settings, user `settings.json`, and workspace `.vscode/settings.json`; later values override earlier ones. Color customizations merge by key. Invalid values are reported, and re-import retains the current preferences if reloading fails.

User `keybindings.json` in the application configuration directory supports JSONC arrays with `key`, `command`, and optional `when` expressions. Chords and boolean expressions using `!`, `&&`, `||`, `==`, `!=`, and parentheses are supported; later matching entries take precedence. Prefix a command with `-` to remove the matching default binding. Context keys include `editorTextFocus`, `editorReadonly`, `editorHasSelection`, `multipleSelections`, `terminalFocus`, `findWidgetVisible`, `findReplace`, `suggestWidgetVisible`, `snippetVisible`, `projectSearchVisible`, and `quickOpenVisible`. Default navigation, editing, clipboard, search, quick open, snippets, completion, group, theme, terminal and LSP shortcuts use the resolver; close confirmations and terminal input still handle their keys separately. Unknown commands are reported in the status bar. Re-importing settings reloads keybindings and retains the previous bindings on an invalid file.

Each tab owns a tree-sitter parser and syntax tree. Edits are applied to that tree and highlighting is recomputed from the containing syntax node through end of file; unchanged preceding lines and inactive tabs retain their cached spans. The accessible tree exposes the tab list and editor; assistive technology can activate tabs, focus the editor, replace its value and set a selection.
