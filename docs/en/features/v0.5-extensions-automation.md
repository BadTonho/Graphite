# v0.5 — Extensions and Automation

Phase 5 is in progress. This page records the current implementation boundary so the roadmap does not imply full VS Code compatibility.

## Available foundations

- The native command palette opens with `Ctrl+Shift+P` or `F1`, filters registered Graphite commands and commands registered by an active host, and excludes disabled entries from execution.
- Workspace trust is opt-in and persisted against a canonical workspace path. `Trust This Workspace` grants trust; `Revoke Workspace Trust` revokes it and stops active plugin hosts. Native Graphite plugin activation still requires its separate per-version trust.
- A local Open VSX registry client supports search, latest-version metadata and bounded VSIX downloads. Registry responses are validated, downloads must use HTTPS outside loopback fixtures, and downloaded archives pass the existing VSIX inspector before installation.
- Task configuration primitives parse `shell` and `process` entries, arguments, working directories, default build groups and named regex captures. The runner refuses to start without workspace trust and supports cancellation and streamed output callbacks.
- The editor expands a limited set of HTML/JSX and CSS abbreviations on `Tab` and through `Emmet: Expand Abbreviation`.
- Profile storage primitives create isolated profile directories and copy existing settings into `Default` without removing legacy files.

## Current limitations

The Code OSS 1.145.2 extension host and its `commands`, `workspace`, `window` and `languages` compatibility bridge are not integrated yet. Open VSX discovery and download are exposed as a library API; the plugin sidebar does not yet install or activate VSIX packages. Graphite's native plugin runtime remains separate.

Tasks are not yet wired to the command palette, `Ctrl+Shift+B`, terminal UI or Problems diagnostics. The current Emmet implementation is a small local subset, not the pinned upstream Emmet implementation. Profile storage is not yet connected to settings, themes, keybindings, snippets and extension-host lifecycle switching. These gaps keep all Phase 5 roadmap items open.

Automated checks are local and do not contact a marketplace. Windows package and application tests have been run during development; full workspace acceptance checks are still pending. Linux has not been tested in this pass.
