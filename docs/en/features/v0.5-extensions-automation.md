# v0.5 — Extensions and Automation

Phase 5 remains in progress. The implementation does not claim general VS Code extension compatibility until the pinned Code OSS host and its Rust main-thread bridge are integrated and validated.

## Implemented foundations

- The command palette filters native Graphite commands, active Graphite plugin commands and configured workspace tasks. Task entries show their origin and cannot run until the workspace is trusted. `Ctrl+Shift+B` selects the default build task.
- `tasks.json` supports shell and process tasks with labels, arguments, working directories, default build groups and regex problem matchers. Tasks run outside the UI thread, stream output into the terminal panel, support cancellation and publish diagnostics for matching open files.
- Workspace trust is opt-in and persisted against a canonical workspace path. Native Graphite plugin activation has an additional per-version trust gate. Revocation cancels the running task, stops active plugin hosts, and invalidates in-flight activation results; trusting again queues previously approved native plugins for activation.
- The Plugins sidebar searches Open VSX, downloads the latest VSIX on a worker, inspects it and asks for confirmation before installation or update. The registry client enforces HTTPS, identity/version checks and bounded downloads. Installed VSIX files remain inactive until the Code OSS host is integrated.
- Emmet uses the upstream `emmet` 2.4.11 package, bundled under its MIT license and accessed through a persistent Node worker. `Tab` and `Emmet: Expand Abbreviation` use the same upstream implementation.
- Profiles persist the active selection and expose create, list and switch commands. Each profile has its own settings, theme, keybindings, snippets, terminal settings and plugin store; the legacy state is copied into `Default` without deleting the original files. Switching profiles reloads these settings and stops profile-owned extension hosts.

## Remaining Phase 5 work

The Code OSS 1.145.2 host (`c4453f8`) is not integrated or packaged. The current Rust process helper uses a Graphite protocol and cannot activate VSIX extensions. The Rust bridge for the public `commands`, `workspace`, `window` and `languages` APIs, lazy Code OSS host lifecycle, extension-specific trust, and local VSIX activation still need implementation.

Workspace trust gates task execution and native plugin activation; Code OSS extension activation still needs its trust gate. Profile state is isolated and switched by commands, while VSIX host lifecycle integration remains pending.

These gaps keep Phase 5 open. Marketplace tests use a local HTTP fixture, not the public service. Windows tests are run for this pass; Linux and native visual validation were not performed.
