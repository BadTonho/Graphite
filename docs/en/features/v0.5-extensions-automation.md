# v0.5 — Extensions and automation

- **Extensions and the palette.** Install or update VSIX packages through the Plugins sidebar and Open VSX. Approve the installed version and trust the workspace before invoking its command from the palette. The portable distribution includes Code OSS 1.145.2 and Node.js 24.22.1. See the [supported API matrix](../architecture/extension-compat.md).
- **Workspace trust.** Restricted workspaces can inspect and install packages. Trust gates tasks, native plugins and VSIX execution. Revocation cancels tasks, stops hosts and discards pending session work.
- **Tasks.** Use shell and process tasks from `tasks.json`. The palette shows task origins, `Ctrl+Shift+B` runs the default build task, and regex problem matchers publish diagnostics.
- **Emmet.** The upstream Emmet 2.4.11 worker expands HTML, JSX and CSS abbreviations through Tab and the palette command.
- **Profiles.** Settings, themes, keybindings, snippets, terminal settings, plugins and VSIX state are isolated by profile. Switching profiles stops the outgoing extension host.

## Validation

The opt-in local VSIX integration test exercises the official host, commands, workspace configuration and edits, prompt cancellation, quick picks, provider results, diagnostics, version approval, trust revocation and host failure. The regular workspace suite uses local fixtures for registry requests.

The public sample is [Sort Lines by Selection 1.0.0](https://open-vsx.org/extension/earshinov/sort-lines-by-selection). Its VSIX SHA-256 is `e70edd326804dcc87f9562f5a93c5f5f6627205b373293664592657a7949a1ec`. The sample test installs that file, selects its palette entry, sorts two selected lines and verifies undo. See [portable package and integration test commands](../contributing/building.md).

On Windows, all 400 standard workspace tests, the workspace build and the formatting check passed. The two opt-in Code OSS tests passed, including a public registry search and download whose bytes matched the pinned VSIX. Native window and GPU interactions were not verified.

Both integration tests also passed against the extracted Windows x86-64 runtime with system Node excluded from the test path. The local verification build compiled `native-watchdog` and `spdlog` without MSVC Spectre mitigation because the matching toolchain libraries were unavailable. The standard build instructions retain the upstream compiler configuration.
