# v0.5 — Extensions and Automation

Phase 5 remains in progress. The implementation is intentionally limited to documented behavior and does not claim general VS Code extension compatibility.

## Implemented foundations

- The command palette filters native Graphite commands, active Graphite plugin commands and configured workspace tasks. Task entries show their origin and cannot run until the workspace is trusted. `Ctrl+Shift+B` selects the default build task.
- `tasks.json` supports shell and process tasks with labels, arguments, working directories, default build groups and regex problem matchers. Tasks run outside the UI thread, stream output into the terminal panel, support cancellation and publish diagnostics for matching open files.
- Workspace trust is opt-in and persisted against a canonical workspace path. Native Graphite plugin activation has an additional per-version trust gate.
- The local Open VSX client provides search, latest-version metadata and bounded VSIX downloads through local-fixture-tested APIs. Registry identity is checked and downloaded archives pass the VSIX inspector before installation.
- Emmet currently supports a tested local subset for HTML/JSX and CSS. It expands on `Tab` when the local parser recognizes an abbreviation and remains available through `Emmet: Expand Abbreviation`.
- Profile storage primitives create isolated directories and copy legacy settings into `Default` without deleting the old files.

## Remaining Phase 5 work

The Code OSS 1.145.2 host (`c4453f8`) is not integrated or packaged. The current Rust process helper uses a simulation protocol and cannot activate VSIX extensions. The Rust bridge for `commands`, `workspace`, `window` and `languages`, lazy host lifecycle, extension-specific trust, and local VSIX activation still need implementation.

Open VSX is not connected to the Plugins sidebar. Emmet is not the pinned upstream implementation. Profiles are not yet connected to application settings, themes, keybindings, snippets, extension stores and host lifecycle switching. Workspace trust currently gates task execution and native plugin activation; host activation still needs its own gate.

These gaps keep all six Phase 5 roadmap items open. Automated tests do not use a real marketplace. Windows tests are run for this pass; Linux and native visual validation were not performed.
