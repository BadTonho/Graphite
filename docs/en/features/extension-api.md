# Extension API surface

VSIX extensions run in the official Code OSS 1.145.2 extension host, in a separate Node process started by `packaging/code-oss/bridge.mjs`. Graphite answers the host's calls to the main thread, so every workbench effect goes through Graphite's own checks (workspace trust, read-only files, and the workspace boundary).

## Supported

| Area | What works |
|---|---|
| Commands | Register, execute, and list commands; Graphite commands can be run by extensions. |
| Configuration | Read values, update and remove workspace or user settings, listen for changes. |
| Storage | Extension global and workspace storage. |
| Prompts | `showInputBox`, `showQuickPick`, and `showInformationMessage` with action buttons. |
| Edits | `TextEditor.edit`, `workspace.applyEdit`, and documents opened or shown in the editor. |
| Language providers | Hover, completion, document formatting, diagnostics, definition, declaration, type definition, implementation, references, document symbols, code actions, rename, and signature help. Also range formatting (**Format Selection**, the cursor line when nothing is selected), inlay hints, document highlights and folding ranges; the last three are requested automatically (see below). Selection ranges drive **Expand Selection** in place of the syntax-tree expansion when an extension provides them. On-type formatting runs while typing when `editor.formatOnType` is on. Call and type hierarchies (**Show Call Hierarchy** / **Show Type Hierarchy**) list callers and callees, or super and subtypes, in the locations picker. Document links are underlined and followed with Ctrl+click. Semantic tokens are drawn over the syntax colors (and language servers feed the same display). Code lenses are shown at the end of their line and run with Ctrl+click there. Colors are tinted and outlined in the text. |
| Links | `window.openUri` opens `https://` links in the default browser; other schemes are refused. `env.asExternalUri` returns the link unchanged. |
| Output | `window.createOutputChannel` writes to a log file. Showing a channel opens its log in a read-only view that refreshes while the extension writes. |
| Status bar | `window.createStatusBarItem` items appear at the end of the status bar with their text. Clicking an item runs its command: an extension command if registered, otherwise a Graphite command. |
| Files | `workspace.findFiles` with include and exclude globs and a result limit, honoring ignore files. `workspace.findTextInFiles` (a proposed API: the extension must list `findTextInFiles` in `enabledApiProposals`) searches the workspace with the project search engine, with regex, case, whole-word and glob options, and stops after 5 seconds. |
| Progress | `withProgress` titles and messages appear in the status bar. |
| Terminal | `window.createTerminal` (with `name`, `shellPath`, `shellArgs`, `cwd`) opens a Graphite terminal tab. `sendText`, `show`, `hide`, `dispose` and `onDidCloseTerminal` with the exit code work. |
| File watchers | `workspace.createFileSystemWatcher` receives create, change and delete events for the whole workspace (except inside `node_modules`) and for folders the extension registers outside it. |
| Clipboard | `env.clipboard.readText` and `writeText`. |
| `workspace.fs` | Answered by the extension host directly on the local disk; it does not go through Graphite. |
| Text decorations | `window.createTextEditorDecorationType` and `TextEditor.setDecorations` draw background colors, borders (`border`, `outline`), whole-line marks and `after` text at the end of a line, with `dark` and `light` variants. Colors can be hex, `rgb()`/`rgba()` or common theme colors. Fonts, gutter icons, overview ruler marks, `before` text and hover messages are ignored, and decorations are not drawn in word-wrap mode yet. Ranges are not adjusted while the document is edited; the extension normally sets them again. |
| Debug adapters | An extension that registers a `DebugAdapterDescriptorFactory` can supply the adapter for its debug type: executable and local TCP server descriptors work. Configuration providers, named pipes and inline implementations are not supported yet. See [Debug panel](debug-panel.md). |
| Webview | Several webview panels, HTML content, messages both ways; resource URIs are confined to `localResourceRoots` (or the extension and workspace roots). |
| Custom editors | A `contributes.customEditors` entry opens its files in the extension's webview instead of the text editor, for providers registered with `registerCustomTextEditorProvider` and `registerCustomEditorProvider`. The extension is activated by `onCustomEditor:<viewType>`, files that match a `priority: "default"` selector open with it, and **Reopen editor with...** (`workbench.action.reopenWithEditor`) lists the other editors and the text editor; that choice is remembered for the file. The page is hosted in an overlay below the tab strip, with `enableScripts`, resource-root confinement and messages in both directions as for other webviews. A **text** editor works on the open text document, so save, undo and redo are the document's own. A **custom** editor owns the document: the text behind it becomes read-only, edits reported by `onDidChangeCustomDocument` make the tab dirty, and Save, Undo and Redo (menu, palette and keys) are sent to the extension as `saveCustomDocument`, `undo` and `redo`. A file opened by an extension (`openTextDocument`) never opens in a custom editor. Backups, saving as, reverting, moving an editor between groups, diff editors and the find widget are not supported. |
| Authentication | `authentication.getSession` and `getAccounts` work for the `github` provider, answered with Graphite's own GitHub sign-in (see [GitHub sign-in](github-sign-in.md)), and for providers an extension registers with `registerAuthenticationProvider` (`getSessions`, `createSession`, `removeSession` and `onDidChangeSessions` are forwarded). An extension receives a session only after the user chose **Allow** for that account in a prompt; the choice is stored per provider, account and extension in `<profile>/code-oss/authentication-access.json`, and an extension that creates the session with `createIfNone` is allowed for it. `silent` requests never prompt and return `undefined` until the extension is allowed. A request for scopes the GitHub sign-in lacks offers a new sign-in with the combined scopes. Signing out of GitHub or calling `removeSession` forgets the allowed extensions of that account. Requests by `WWW-Authenticate` challenge and dynamic (OAuth server) providers are not supported. |
| Virtual file systems | `workspace.registerFileSystemProvider` serves a URI scheme. Opening a `scheme:` document (`openTextDocument`, `showTextDocument`, or a click in the explorer) reads it through the provider into a local mirror under `<profile>/virtual-fs/<scheme>/<authority>/<path>` and opens that file, so highlighting and language servers work as for any file. Extensions see the document under its virtual URI, and saving writes the mirror back with `writeFile`. A clean document is refreshed from the provider each time it is opened; one with unsaved edits keeps them. Each registered scheme appears in the explorer below the workspace tree as a folder `scheme:/` whose subfolders are read with `readDirectory` when expanded and re-read on `onDidChangeFile`. Graphite watches the root with `watch`. Providers that declare the `Readonly` capability are recorded as such. Delete, rename and stat calls exist for the explorer but no menu uses them yet, and the query part of a URI is not part of a file's identity. |
| Source control | `scm.createSourceControl` providers appear in the Source Control panel below the Git changes: a header with the label and count, a commit box, collapsible resource groups (honoring `hideWhenEmpty`) and the resources with their tooltip, strike-through and faded decorations. Typing in the box updates `inputBox.value` and `Ctrl+Enter` (or the check button) runs `acceptInputCommand`. Clicking a resource runs the command attached to it; a `file:` resource without a command opens as a file. Without a Git repository the panel lists only the extension providers. Quick diff, the history provider and the action button are not shown. |
| Webview views | A `contributes.views` entry with `"type": "webview"` is served by `window.registerWebviewViewProvider`. Graphite calls `resolveWebviewView` the first time the view is shown, hosts its page in an overlay over the side bar under a header row, and reports visibility changes (`onDidChangeVisibility`). Scripts run only when `enableScripts` is set, and a restrictive Content Security Policy always applies. Views and `postMessage` work both ways, and `title`, `description` and `badge` update the header. A hidden view drops its page and rebuilds it from the last HTML, unless the provider sets `retainContextWhenHidden`. Several webview views in one container share the height; next to tree views they take the lower half. `WebviewView.show()` reveals the container. |

## Declarative contributions

A VSIX without a Node.js entry point (themes, snippets, language packs) runs no code, so it can be enabled without starting the extension host. Applied contributions:

| Contribution | What happens |
|---|---|
| `commands` | Declared commands appear in the palette before the extension activates. |
| `languages` configuration | Line and block comment markers feed Toggle Line/Block Comment. |
| `viewsContainers.activitybar` | Containers appear in the activity bar. |
| `snippets` | Snippet files are loaded for enabled extensions, scoped to the contributing language. A user or project snippet with the same prefix and scope overrides them. |

| `themes` | Color themes are imported into the profile and selected with `workbench.colorTheme`, by label or id. Disabling the extension removes them. |
| `iconThemes` | File icon themes are selected with **File Icon Theme** or `workbench.iconTheme`, and drawn in the Explorer, Quick Open, tabs and Source Control. See [File icons](file-icons.md#icon-themes-from-extensions). |

Keybindings are bound into the active keymap when the extension is approved and the workspace is trusted. Grammars are listed in the package but not applied yet.

## Not yet

- Language providers beyond the list above (none left that Graphite knows of; the color picker and color presentations are not supported). Code actions that only run an extension command, and file operations inside a rename, are not applied.
- Notebook kernels.

Requests outside this list get the error `Graphite does not support <actor>.<method>`, and the extension sees that error. Registrations of capabilities that are not implemented (`$register*`, `$unregister*`, `$emit*`) are accepted without an error so they do not clutter the status bar. Every unsupported call is recorded once per session in `<profile>/code-oss/unsupported-api.log`, which shows what an extension needs that Graphite does not provide yet.

Commands are tracked the same way. When an extension calls `commands.executeCommand` with an id Graphite does not have, or runs a code lens whose command Graphite cannot run, the id is counted, and **Show commands requested by extensions** opens a read-only list of them (requests, command id, whether it came from extension code or a code lens), most requested first. Each id is also appended once to `<profile>/code-oss/requested-commands.log`. Use the list to see which commands to implement for an extension to work; the list is rebuilt from the current session, the log keeps ids across restarts.

## Features requested automatically

Most providers answer a command (hover, go to definition, format). Seven are asked for without one:

- **Inlay hints** (`registerInlayHintsProvider`): for the active document, whenever its text changes. They are shown by the same inline-hint display that language servers use, and only when no language server serves that file, so the two never compete. A provider that fails is not asked again until the document changes.
- **Document highlights** (`registerDocumentHighlightProvider`): for the symbol at the cursor, once the cursor has rested for 150 ms. Occurrences are drawn with the editor's word-highlight color. Highlights are removed as soon as the cursor moves, and an answer for a position the cursor has left is dropped.
- **Folding ranges** (`registerFoldingRangeProvider`): for the active document, whenever its text changes. While a provider's regions describe the current text, they replace the indentation rules for every fold command and for the fold display; until the first answer, or after an edit, indentation folding applies. Regions that do not span two lines are dropped, and a failing provider is not asked again until the document changes.
- **Document links** (`registerDocumentLinkProvider`): for the active document, whenever its text changes. Links are underlined; Ctrl+click on one opens `https:` links in the browser and `file:` links in the editor. Links the provider leaves unresolved (no URL yet) are reported but not followed, and the underlines disappear as soon as the text is edited, until the extension answers again.
- **Semantic tokens** (`registerDocumentSemanticTokensProvider`): for the active document, whenever its text changes. The provider's full answer (token type, position and length per token) is decoded, each token type is mapped to the nearest syntax class (types, functions, variables, properties, keywords, comments, strings, numbers, operators; other types keep the syntax color) and drawn over the tree-sitter highlighting. Tokens describe one revision of the text, so after an edit the syntax colors show until the provider answers again. Only whole-document answers are understood: delta answers, range providers and token modifiers are not used. The extension host sends the binary answer to Graphite as 32-bit words, and the decoding follows Code OSS's layout from the protocol description; it has been tested with synthetic answers, not with a real language extension.
- **Code lenses** (`registerCodeLensProvider`): for the active document, whenever its text changes. Graphite has no room between editor lines, so each lens is shown as muted text at the end of its line, several lenses on a line joined with ` | ` in column order. Lenses that arrive without a command are resolved one by one (up to 50 per document revision) and the text fills in as answers come back. Ctrl+click at the very end of a line, or **Run code lens on current line**, runs the first lens of that line: a Graphite command is run with the lens's first argument, an extension command is run in the extension host with all its arguments, and any other command (for example VS Code's built-in `editor.action.showReferences`) is reported as unavailable. The text disappears when the document is edited, until the provider answers again.
- **Colors** (`registerColorProvider`): for the active document, whenever its text changes. Without inline widgets there is no square before the text: each color range is drawn with a translucent background in that color and an outline of the same color. Colors disappear as soon as the text is edited, until the provider answers again. Picking another color from a swatch (`provideColorPresentations`) is not supported.

Both are requested only in a trusted workspace, for the active document, and answers for an outdated document revision are discarded. Each request has a 10-second limit. These paths are covered by unit tests that play the extension host's side of the protocol; they have not been run against third-party extensions.

### On-type formatting

With `"editor.formatOnType": true` (off by default, like VS Code), typing one of the trigger characters an extension registered with `registerOnTypeFormattingEditProvider` asks it to format around the cursor; the edits are applied as one undoable step. Only single typed characters count (not pasted text), only with one cursor, and only if the document did not change meanwhile. Typing Enter does not trigger it yet.
